# CLAUDE.md — SBU Beacon Nav

BLE-beacon indoor positioning demo for Stony Brook's New Computer Science (NCS) building, rendered in 3D on the web. Built for the VIP295 "Tech Businesses in Development" team. Owner: 지율 (Jiyul).

## Read first
- `docs/HANDOFF.md`: **current state and exact next steps. Start here.**
- `docs/SPEC.md`: what to build (milestones M1–M6, in priority order) and fixed decisions
- `docs/superpowers/plans/2026-09-30-beacon-nav.md`: task-by-task plan (Tasks 1–6 done; 7 = deploy)
- `docs/RESEARCH.md`: why things are the way they are (Korean). Key facts: iOS can't scan BLE from the web; iBeacon is blocklisted in Web Bluetooth, so we use Eddystone-UID; weighted-centroid + Kalman beats trilateration under realistic noise. (§4 holds this repo's `npm run bench` numbers.)
- `docs/FLOORPLAN_TRACING.md`: how the official floor-plan images became venue JSON (scale, registration, helpers)
- `docs/benchmark-sim.md`: simulated accuracy tables (generated by `npm run bench`)

## Commands
- `npm run dev`: local dev server
- `npm test`: vitest (engine unit + simulated integration tests). Must stay green.
- `npm run trace`: regenerate `src/data/ncs.json` from `scripts/trace-ncs.mjs`
- `npm run bench`: simulated accuracy; rewrites `docs/benchmark-sim.md` and `src/data/bench.json` (the panel's table). Re-run when the venue, tour, radio model or engine changes
- `npm run build`: typecheck + production build (deploy target: Vercel, static)

## Architecture
```
src/
  data/      schema.ts (Venue/Floor/Space/Beacon types), ncs.json (traced, generated by scripts/trace-ncs.mjs), venue.ts (typed loader),
             tour.ts (looping simulated walk), bench.json (generated by npm run bench)
  engine/    pure TS, no React/three imports:
             pathLoss -> filters (EMA/Kalman) -> estimators -> locator (floor detection + space lookup)
             simulator (seeded RSSI generator used by the demo and tests), evaluate (walk/standAt scoring for tests + bench),
             fixture.ts (synthetic venue for unit tests), integration.test.ts (NCS + tour end to end)
  live/      eddystone.ts (Eddystone-UID parser, tested), scanner.ts (requestLEScan, feature-detected; Android/macOS Chrome + flag)
  scene/     react-three-fiber components: Building (slabs with voids, spaces, floor focus), Markers (beacons, truth, estimate, trail)
  ui/        Panel.tsx (mode, method, readouts, heard beacons, simulated-accuracy table)
  App.tsx    main loop: every 250 ms sample (sim) or drain BLE buffer (live) -> locator.ingest -> locator.locate -> render
scripts/     trace-ncs.mjs (pixel trace + calibration -> ncs.json), bench.ts (simulated accuracy tables)
```
Coordinates: building-local meters, x = east, y = north (plan-up; true north is ~9° west of plan-up), origin = SW corner of the footprint. Three.js mapping is (x, elevation × STACK_SCALE, -y) (STACK_SCALE = 2.2 is visual only, so stacked floors can be seen between); floor groups are rotated -90° about X, so polygons are drawn in (x, y) and extruded upward.

## Rules
- Keep `src/engine` framework-free and covered by tests. Add a test for every estimator/filter change.
- Venue data must follow `src/data/schema.ts`. Edit geometry in `scripts/trace-ncs.mjs`, then `npm run trace`; never hand-edit `ncs.json`.
- Never invent room numbers (the official plan has none). Use only labels the plan shows; otherwise use descriptive names ("West corridor").
- Floor-plan images are © Mitchell | Giurgola: keep them out of git and out of the deployed bundle (`docs/floorplans/` is ignored).
- Accuracy claims in UI/docs must come from `npm run bench` or real measurements, and must be labeled as simulated when they are.
- No backend and no location telemetry. Everything stays client-side.
- UI text is English (audience: US professor/classmates). Docs for the owner may be Korean.
- The owner prefers plain, un-decorated UI: no emoji icons, no marketing slogans.
- Pushing to GitHub (public repo) and deploying are outward-facing: report what goes out and get the owner's OK first.
